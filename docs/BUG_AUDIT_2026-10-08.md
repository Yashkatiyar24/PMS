## Backend (15)

1. **High · CONFIRMED** — `jobs/DailyReportJob.java:34-38`, `reports/ReportService.java:31-37`. `businessDay(D)` = `[D@start, D+1@start)`; job fires at 21:00 with `businessDate = today` → reports the window that just opened (empty) and claims the key so it never re-runs. Fix: `businessDate = now.toLocalDate().minusDays(1)`.
2. **High · CONFIRMED** — `folio/ReceiptService.java:70-76` `issueInvoice` has no already-invoiced/settled check; `FolioService.removeLine` (164-173) and `refund` (247-252) ignore `status`. Double-click → two numbered invoices; settled folio mutable; `paid < total` and folio vanishes from `outstanding()`. Fix: refuse when an invoice receipt exists; require `status == open` like `addLine`.
3. **Medium · CONFIRMED** — `jobs/NoShowJob.java:29-31`, `DailyReportJob.java:36-37`, `PhotoPurgeJob.java:41-44`. `job_runs` claimed in its own tx before the work; any failure skips that property for the day. Fix: claim+work in one tx, or release claim on failure.
4. **Medium · CONFIRMED** — `auth/BillingGate.java:29-32` + `SessionAuthFilter.java:63-66,83-86`. `must_change_password` user at a `readonly`/`closed` org gets 403 on `POST /api/users/me/password`. Fix: exempt `/api/users/me/**` from BillingGate.
5. **Medium · CONFIRMED** — `folio/FolioService.java:119,147`, `tax/TaxRuleController.java:531`. `LocalDate.now()` (server zone) for `line_date`. Fix: `LocalDate.now(propertyZone)`.
6. **Medium · PLAUSIBLE (design)** — `folio/FolioService.java:146` discounts carry `tax_rate_bp=0`, so GST is computed on pre-discount value (₹5,000@5% −₹1,000 = ₹4,250 not ₹4,200). Decide: negative tax on discount lines or re-price net.
7. **Medium · CONFIRMED** — `jobs/PhotoPurgeService.java:34-41`. Guest with zero bookings matches `not exists(...)` → ID photo purged next night despite 730-day retention. Fix: also require `exists (bookings where guest_id = g.id)`.
8. **Medium · PLAUSIBLE** — `payments/PaymentService.java:171-179`. Gateway refund called inside tx with no `for update`; DB failure after → money gone, no row; concurrent refunds both pass the cap check. Fix: lock payment row, write pending refund first.
9. **Medium · CONFIRMED** — `booking/BookingService.java:291-294, 334-337`, `FolioService.java:185-188`. Concurrent replays of one `clientUuid` → unique violation → 409 instead of returning the existing record; `recordPayment` check ignores `folioId`. Fix: `insert … on conflict do nothing returning` + re-select, or catch `DuplicateKeyException`.
10. **Low · PLAUSIBLE** — `reports/ReportService.java:245-252` cash handover race: two managers → cash counted twice. Fix: `for update` on un-handed payments.
11. **Low · CONFIRMED** — `channels/PublicChannelController.java:83-93`. Replayed public booking POST mints a new stay link and a new Razorpay order each time; two completed checkouts both recorded. Fix: reuse open `payment_orders` for existing booking.
12. **Low · CONFIRMED** — `selfreg/SelfRegistrationService.java:158-163` `apply()` ignores `state == revoked`. Fix: allow only `open`/`submitted`.
13. **Low · CONFIRMED** — `charges/ReceiptNumberFormat.java:21`, `settings/SettingsRegistry.java:90-91`. `{PREFIX}/{FY}/{SEQ:4}` hits the 16-char limit at seq 10,000 → no receipts until settings changed. Fix: validate width at settings save.
14. **Low · PLAUSIBLE** — `folio/FolioService.java:293-302` `recompute()` without row lock → concurrent payments can leave `paid_paise` stale. Fix: `select … for update` on the folio.
15. **Low · CONFIRMED (latent)** — `tenant/TenantDataSource.java:47-51` guard passes inside an `adminTx` → silent empty RLS results if ever misused. Fix: check `hasResource(targetDataSource)`.

**Verified OK:** RLS/tenant plumbing on every table (V1–V28), session/OTP/lockout/CSRF/CORS, Razorpay signature + idempotency per gateway payment id, integer-paise math & GST split, gap-free counters, public token hashing, SSRF guard, upload sniffing, outbox.
