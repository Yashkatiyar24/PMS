# Build prompts

Ten prompts, one per build step, written for an AI coding agent (Claude Code, Cursor, Copilot Workspace). Paste them in order into the same repo; each one ends with a verification the agent must pass before you move on. Run Prompt 0 first and keep its file in the repo so every later prompt inherits the rules.

## Prompt 0 — Project context (run once, commit the file)

Save the output as `CLAUDE.md` at the repo root (or `.cursorrules`). Every later prompt starts with "Follow CLAUDE.md".

```
Create a file CLAUDE.md at the repo root with these project rules, then stop.

# Project: Dharamshala PMS
A multi-tenant property management system for small Indian dharamshalas and hotels.
V1 replaces the paper guest register, receipt book and month-end ledger. Nothing more.

## Non-negotiable rules
- Multi-tenant: one Postgres schema; every tenant table has property_id UUID NOT NULL and Row Level Security. The app sets `SET LOCAL app.property_id = $1` at the start of every DB transaction from the session. Never query a tenant table without it.
- Money is BIGINT paise. Never float. Display as ₹ with Indian grouping (1,00,000.00).
- Timestamps TIMESTAMPTZ; stay dates DATE (check_out exclusive). Financial year April–March.
- Double booking is impossible at the DB level (exclusion constraint on booking_units), not only in UI.
- Every write to bookings, booking_units, folios, folio_lines, payments, rooms, receipts writes an audit_log row (user, before, after).
- Receipt numbers are gap-free per property per FY, allocated inside the same transaction with SELECT ... FOR UPDATE on receipt_counters.
- Never store an Aadhaar number. ID = type + last 4 digits + photo in object storage (R2), served by signed URL.
- Outbound messages (WhatsApp/SMS/email) go to the outbox table; a worker sends them. Never send inside a request.
- UI: mobile-first at 360 px, tap targets >= 44 px, Hindi + English strings from packages/i18n/{hi,en}.json. No English-only screens.
- Offline: check-in, checkout, payment forms must queue in IndexedDB when offline and sync when back.

## Stack
Next.js 15 App Router + TypeScript, Tailwind, Drizzle ORM + drizzle-kit, Postgres 16, PgBouncer, pg-boss for jobs, Zod for validation, Playwright for tests, Docker Compose, Caddy. Monorepo with pnpm workspaces:
apps/web, packages/db, packages/jobs, packages/pdf, packages/i18n, infra/.

## Roles
owner (all properties of an organisation, billing, users), manager (one property, all operations, corrections), staff (check-in/out, payments, housekeeping; cannot edit past-day records). super_admin is us: separate DB role, RLS bypass, every access logged.

## Working style
- Small commits, one feature per prompt. Run `pnpm lint && pnpm typecheck && pnpm test` before declaring done.
- Migrations are SQL files generated by drizzle-kit; show me the SQL before applying anything that drops or alters a column.
- When unsure about a business rule, read docs/PRD.md and ask one question rather than guessing.
```

## Prompt 3 — Walk-in check-in, guests, ID photo, Today view (week 3)

```

Guests
1. Guest lookup by phone within the property: typing a 10-digit number shows an existing guest to reuse. Fields: name, phone, city, id_type (aadhaar, voter, dl, passport, other), id_last4, adults, children. Reject any 12-digit numeric value in id_last4 or notes (never store Aadhaar).

Check-in
3. Single-screen form: guest (lookup or new) → adults/children/member_count → pick room or bed from a list of free units for tonight (grouped by room type, rate shown) → nights (default 1) → advance paid (amount + mode cash/upi) → Save.
4. Save is one transaction inside withTenant: upsert guest, insert booking (state checked_in, source walk_in, check_in today, check_out today + nights), booking_units per room/bed with rate_paise, folio, folio_lines of kind room_night per night, payment row if advance > 0, audit_log rows. 5. If the unit was taken meanwhile, the exclusion constraint fires; map it to a friendly error and refresh the free-unit list.

Today view (default landing screen)
6. Sections: Arrivals today (reserved bookings), In-house (checked_in), Departures today (check_out = today), Free rooms/beds count by type. Each row opens the stay. One big "Check-in" button.
```

## Prompt 4 — Folio, payments, GST, receipts, printing (week 4)

```
Follow CLAUDE.md. Build money handling and receipts.

Folio
1. Folio page for a stay: lines grouped by date; add extra (description, qty, unit_paise), add discount (manager only, reason required), remove a line (manager only, writes audit_log). Room-night lines recompute automatically when dates change (hook for Prompt 5).
2. Tax engine in packages/db/src/tax.ts, pure function: given property settings (gstin present?, donation_mode) and a room-night unit rate, return tax_rate_bp: 0 if no GSTIN or donation_mode; 500 (5%) if rate <= 7,50,000 paise per night; 1800 (18%) above. Rates come from a `tax_rules` JSON in settings with effective_from dates so a slab change is data, not code. Tax is a separate folio_line of kind tax per room_night group. Unit tests for every branch and the boundary at exactly ₹7,500.
3. Totals cached on folios (total_paise, paid_paise) and recomputed inside the same transaction as any line/payment change.

Payments
4. Record payment: amount, mode (cash/upi/card/bank), reference (UPI ref optional), received_at default now, received_by = current user. Multiple partial payments allowed; balance shown live. Refund = manager only, is_refund true, reason required.
5. Show a static UPI QR (property settings: upi_vpa, payee name) on the payment sheet and on receipts, generated client-side with the upi:// intent string and the amount prefilled.

Receipts
6. packages/pdf: HTML templates rendered to PDF with Playwright/Chromium in the jobs container. Two templates: invoice (GST fields, HSN 9963, tax breakup, receipt number, property header/footer) and donation receipt (80G number, "no goods or services" line). Both in Hindi+English labels. Two CSS print sizes: A4 and 58 mm thermal.
7. Receipt numbering: receipts.number = `${prefix}/${fy}/${seq padded 4}`; allocate with SELECT last FROM receipt_counters WHERE property_id=$1 AND fy=$2 FOR UPDATE, insert counter row if absent; all inside the transaction that inserts the receipt. Voiding sets voided_at and keeps the number.
8. Receipt generated at check-in (advance receipt) and on demand from the folio page; "Print" opens the PDF in a new tab with window.print(); "Send on WhatsApp" enqueues an outbox row with the PDF key (sending is Prompt 7).

Tests
- vitest: tax engine branches; receipt numbers are gap-free and unique under 20 concurrent allocations; totals equal sum of lines after random add/remove.
- Playwright: add an extra, record two partial payments, generate and open the receipt PDF, assert the number format and that balance is zero.

Done when a receipt prints correctly on A4 and 58 mm (attach both PDFs) and all tests pass.
```

## Prompt 5 — Checkout, advance booking, tape chart (week 5)

```
Follow CLAUDE.md. Complete the booking lifecycle (PRD Flows B and C and the state diagram).

Checkout (Flow B)
1. Checkout action on a stay: shows folio balance; if balance > 0 requires a payment first (or manager override with reason, written to audit_log); sets state checked_out, checked_out_at now, sets each unit's room status to dirty, generates the final receipt, enqueues the checkout WhatsApp message.
2. Early checkout: reduces nights and removes future room_night lines (and their tax) with audit. Late checkout beyond the property's checkout time adds a configurable late fee line (settings.late_checkout_paise, default 0).

Advance booking (Flow C)
3. New booking screen: guest (lookup/new), check_in and check_out dates, room type (required) and optional specific room/bed, adults/children/member_count, advance amount + mode, notes. Creates state reserved and booking_units for the chosen unit; if only a type is chosen, hold a unit of that type by inserting a booking_unit on the first free unit (so the exclusion constraint still protects it) and mark it `auto_assigned`.
4. Convert reserved → checked_in from Today view Arrivals with one tap (opens the check-in form prefilled). Cancel with reason (manager); cancelled sets cancelled_at on units so they no longer block the calendar.
5. No-show handling: a job at settings.noshow_hour (default 18:00) flags reserved bookings not checked in today as `flagged_noshow` (badge in Today view); nothing is auto-cancelled.

Tape chart
6. /bookings/chart: rows = rooms (dormitory rooms expand to beds), columns = 14 days from a selectable start, horizontally scrollable, sticky room column. Cells coloured by state (reserved, checked_in, blocked room, free). Tap a free cell to start an advance booking prefilled with that unit and date; tap a booking to open it. Server query returns units for the window in one round trip; must render 100 rooms x 14 days in under 1 s server time (add an index on booking_units(property_id, check_in, check_out)).
7. Change room / extend stay / shorten stay from the stay page; each re-writes booking_units inside a transaction and relies on the exclusion constraint for conflicts.

Tests
- vitest: extend into an occupied night fails; cancel frees the unit; auto-assign picks a free unit and never double-holds.
- Playwright (360 px): create an advance booking from the chart, see it on Today Arrivals on that date, convert to check-in, checkout with balance zero, room becomes dirty.

Done when the state diagram in the PRD is fully reachable from the UI and tests pass.
```

## Prompt 8 — PWA offline queue, Hindi pass, backups, monitoring (week 8)

```
Follow CLAUDE.md. Make the app survive bad networks and bad days.

PWA and offline
1. Add a service worker (next-pwa or Serwist): precache the app shell; network-first for API with a cache fallback for GET /api/today, /api/rooms/free and the last 7 days of /api/bookings.
2. Offline write queue in IndexedDB (Dexie): check-in, checkout, payment and housekeeping-status submissions are stored with a client-generated UUID and a monotonic sequence when navigator.onLine is false or the request fails with a network error. A sync worker replays them in order when online; the API accepts the client UUID as an idempotency key so a replay never duplicates. Conflicts (unit no longer free, stay already checked out) are shown in a "Needs attention" list, never dropped.
3. Receipt for a queued check-in prints from local data with the number "PENDING" and is replaced by the real number after sync (the receipt is regenerated then).
4. Visible offline banner and a queue counter in the header.

Hindi and UI pass
5. Extract every user-visible string to packages/i18n/{en,hi}.json; fail the build (lint rule or test) on a hard-coded string in apps/web. Fill hi.json with natural Hindi (Devanagari), not transliteration. Dates DD-MM-YYYY, amounts with Indian grouping everywhere. Add a font-size toggle (normal / large) and check contrast >= 4.5:1.

Backups
6. infra/backup.sh: nightly pg_dump | gzip → rclone to R2 bucket `pms-backups/YYYY/MM/DD.sql.gz`; keep 30 daily and 12 monthly; a pg-boss job runs it at 02:30 IST and enqueues an email to the team on failure. infra/restore.sh restores a chosen dump into a scratch Postgres container and runs a sanity query (row counts by table); document the monthly restore drill in infra/README.md.

Monitoring
7. Sentry in web and jobs (DSN from env, PII scrubbed: no guest names or phones in events). Uptime Kuma container in docker-compose pinging /health every minute with a WhatsApp/email notification to the team. /health returns DB, PgBouncer, R2 and outbox lag status.

Tests
- Playwright with network offline: complete a check-in, see it queued, go online, see it synced with a real receipt number; create a conflict on purpose and see it in Needs attention.
- vitest: idempotent replay of the same client UUID creates one booking.

Done when a full day of the pilot desk can be simulated with the network toggled on and off without losing a single entry, and the backup and restore scripts both succeed locally.
```
